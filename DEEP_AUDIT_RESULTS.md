# Детальный аудит - Дополнительные исправления

## Найденные и исправленные проблемы

### 1. КРИТИЧЕСКАЯ ПРОБЛЕМА БЕЗОПАСНОСТИ: Повторное использование кода восстановления

**Проблема:**
В `/api/auth/recovery/reset` код удалялся из `pendingTgLogins` только после успешного обновления пароля в БД. Если произошла ошибка при обновлении пароля, код оставался в памяти и мог быть использован повторно для сброса пароля.

**Исправление:**
Код теперь удаляется сразу после валидации, до хэширования пароля. Это предотвращает повторное использование кода даже при ошибках БД.

**Строки:**
- Было: код удалялся в строке 832 (после успешного обновления БД)
- Стало: код удаляется в строке 818 (сразу после валидации)
